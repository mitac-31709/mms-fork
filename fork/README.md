# Meister Management System のフォーク

元アプリ（`https://meister.tokyo-ct.org`）の画面を、UI を使いやすくして作り直したもの。
設計システムは `design.md` に固定してある。指摘の出どころは `../audit/HALLMARK_AUDIT.md`。

## 画面

| ルート | 画面 | 元アプリ |
| --- | --- | --- |
| `/dashboard` | ダッシュボード（他画面の件数と期限の近い週報。元は「調整中」だけ） | `/dashboard` |
| `/orders` | 注文 | `/orders` |
| `/equipments` | 利用可能な機材 | `/equipments` |
| `/loans` | 機材貸出 | `/loans` |
| `/reports` | 週報一覧 | `/reports` |
| `/notifications` | 通知 | `/notifications` |
| ログイン画面 | 元アプリの Devise に中継 | `/users/sign_in` |

`/orders/new`（注文の作成フォーム）と TA / 管理者画面はフォークしていない。
前者は元アプリへ案内し、後者は検証に使えるアカウントで実物を見られなかったため。

**画面ごとに HTML を複製していない。** 共通のシェル（`index.html`）にレール・
詳細パネル・トーストを 1 組だけ持ち、中身をクライアント側で差し替える。
複製は元 UI の指摘 11（空状態のマークアップが 2 重）と同じ問題を自分で作ることになる。

## ログイン

誰でも自分の元アプリのアカウントで使える。フォーク側に共有の資格情報は無い。

メールアドレスとパスワードは Worker が元アプリの Devise にそのまま中継し、
返ってきたセッション Cookie を暗号化して自ドメインの Cookie に入れる。
資格情報は保存しない。詳細と限界（元アプリが `cookie_store` なので
サインアウトで発行済み Cookie を無効化できない）は `../deploy/README.md`。

## データの出どころ

通常は Worker の `/api/*` から**元アプリの実データ**を取る。

| 開き方 | 出どころ |
| --- | --- |
| ログインして使う | 元アプリの実データ |
| `?demo=1` を付ける | 同梱のデモデータ（キャッシュ・裏更新・先読みも再現） |
| 静的配信だけ（`/api/*` が無い） | デモデータに自動で落ちる |

どちらを見ているかは本文の上に必ず出る。実データを「ダミー」と書かないよう、
注記も出どころで書き分ける。取得時刻の横の「更新」で、鮮度に関係なく
元から取り直せる。

### デモでキャッシュ挙動を見る

`?demo=1` では Worker と同じ見え方を短い時間で再現する。

1. 画面を開く → 「デモ · キャッシュ（裏で更新中）」が即出る
2. 約 0.7 秒後 → 「デモ · 最新データ」に差し替わり、ダッシュボード等の文言に
   「デモ再取得 #2」が付く
3. すぐ別画面へ → 先読み済みなら即表示
4. 約 8 秒以内に戻る → 「デモ · キャッシュ」（再取得なし）

## 動かす

静的配信だけ（デモデータになる）。

```bash
cd fork
python3 -m http.server 8081
# http://localhost:8081/?demo=1
```

実データでログインから試すなら Worker 経由。

```bash
cd ../deploy && npx wrangler dev --port 8788
# http://127.0.0.1:8788/
```

## 検証

```bash
python3 test_responsive.py                       # 幅と挙動（要 playwright と Chrome）
python3 test_pages.py                            # 実データにしか出ない形に対する描画
cd ../deploy && python3 test/e2e.py              # ログインから 6 画面・ログアウト
cd ../deploy && node --test test/*.mjs           # パーサと API
```

`test_pages.py` が見ているもの。デモデータは「きれいな形」しか含まないので、
実データで来る値の欠けを payload で直接渡して確かめる。

- 通知の `read` が `null` のとき既読かどうかを主張しない（状態は `—`）
- 通知のパネルから既読にできる（デモではローカル更新）
- 通知の `unreadText` が `null` のときリード文を出さない
- 機材の `action` を元アプリの絶対 URL に解決し、別タブで開くことを示す
- 機材の `meta` が `null` のとき空の欄を作らない
- 注文の金額が数値にならないとき元の文字列を出す（`¥0` にしない）。0 円は出す
- 注文ステータスに色とグリフが付く（保留中 / 受取済みなど）
- どのリストも 0 件のときに元アプリの空状態の文言を出す
- 渡していない貸出の節を作らない
- 注記を実データとデモで書き分ける（実データを「ダミー」と書かない）

`test_responsive.py` が見ているもの:

- 320 / 375 / 414 / 768 / 1024 / 1280 / 1920px で横スクロールが出ない
- クリックできる文字が 2 行に折り返さない
- `:focus-visible` / `:active` / `:disabled` / hover が定義されている
- データの出どころが画面に出ている
- 絞り込みと並べ替えでページが再読み込みされず、状態が URL に同期される
- ステータス切替でスクロールが飛ばない
- パネルが Escape と背景クリックで閉じ、フォーカスが呼び出した行へ戻る
- パネルを閉じても本文が保持される
- 削除に確認ダイアログが出ず、連続削除でもトーストが積まれて元の位置に復元される
- トーストがパネルの操作ボタンに重ならない

## 元 UI から直したこと

`../audit/HALLMARK_AUDIT.md` の指摘との対応。

### 見た目

| # | 指摘 | 直し方 |
| --- | --- | --- |
| 1 | ヘッダカード・全テーブルヘッダ・空状態・トップページのパープルグラデーション | 全廃。アクセントはコバルト 1 色で、現在地・フォーカス・主ボタン・選択行だけに使う |
| 2 | display も body も Inter | display に Space Grotesk、ラベルと数字に JetBrains Mono。body は Inter を引き継ぐ。日本語は同じスタックの後段（Zen Kaku Gothic New / Noto Sans JP） |
| 3 | カードの中のカード | 包む層を 1 つに。テーブルは 1px の罫線で区切る |
| 6 | `<th>` にグラデーションと 2px の下罫線、`py-4 px-6` で 1 行 56px | ヘッダは 1px 罫線と小さいラベル書体。行は 54px に詰めて全行そろえた |
| 5 | 列見出し 5 つ全部に装飾アイコン | 落とした。列名は文字だけ |
| 14 | 集計チップが 12px でヘッダに埋もれる | 数字を 28px、ラベルを 11px にして数字を主役にした |
| 15 | `z-[60]` の直値 | `--z-*` の名前付きスケール |
| 16 | Tailwind と DaisyUI の語彙が混在 | トークンを 1 系統に統一 |
| 17 | 数字に `tabular-nums` が無い | 期間・期限・作成日・集計に指定 |
| 18 | Inter の weight を 100–900 全部読み込み | 使う 5 weight だけ |

### 操作性

| # | 指摘 | 直し方 |
| --- | --- | --- |
| 4 | `main.pt-20 > .h-screen.overflow-hidden > .overflow-y-auto` で二重スクロール | スクロールは文書 1 つに集約。列見出しを `sticky` にした |
| 7 | ソートも検索もフィルタも無い（フィルタ枠だけ空で存在） | タイトル検索、ステータスの絞り込み、5 列のソート、並べ替えの選択を追加 |
| 8 | ソートが `window.location.href` で全体を作り直す | DOM 内で完結。状態は `?q=&status=&sort_by=&sort_direction=&report_id=` に同期してリンクは共有できるまま |
| 9 | スライドオーバーに Escape も背景も `role="dialog"` も無い | `role="dialog"` + `aria-modal`、Escape と背景クリックで閉じ、開いたら中へフォーカス、閉じたら呼び出した行へ戻す。裏側は `inert` |
| 10 | 閉じるたびに中身を捨てるので開き直しが毎回フェッチ | 閉じても保持。開き直しで取り直さない |
| 11 | 空状態のマークアップがデスクトップ用とモバイル用に複製 | 1 箇所だけ。768px 未満のカード表示は CSS で切り替える |
| 12 | 削除がネイティブの `confirm()` | 実行してから「元に戻す」を 10 秒出す |

- 元 UI に無かった追加

- 期限に残り日数を添える（「△ 14日超過」「本日締切」「残り7日」）。既存の期限日から導けるので新しい事実を作っていない
- 絞り込みで 0 件になったときは、そもそも 0 件のときと文言を言い分けて「絞り込みを解除」を出す
- キーボード操作。`j` / `k` / `↑` / `↓` で行移動、`Enter` で開く、`Escape` で閉じる、`/` で検索欄へ
- 他人が編集中の項目を読み取り専用にして地の色でも示す（元アプリの `collaborative_edit_controller` に根拠がある挙動）
- **変更通知の届け先。** 未読が増えたらブラウザ通知と Discord へ転送（通知画面。初回だけ開いて見せ、閉じる／保存後は折りたたみ。どちらもオフ可）。ブラウザ通知はタブが開いている間だけ、という制限を画面に明示。Discord は保存時にテスト送信し、成功したらタブ閉鎖後も Cron で送る購読を登録する
- **ダッシュボード。** 元アプリは「調整中」の 1 行だけなので、週報・注文・貸出・通知から件数と期限の近い未完了を組む。無い数字は作らない

## 推測で埋めなかったところ

クローンは一般ユーザー権限で取得した（`../clone/NOTES.md`）。
2026-08-31 に週報 1 件を確認した。見ていない部分は作らずに残してある。

- **ステータスは 未完了 / 完了 の 2 値だけ。** 「下書き」「差し戻し」などの中間状態は作っていない
+ **週報のステータスは 未完了 / 完了 の 2 値。** 注文は元アプリの現行どおり
  保留中 / 注文済み / 受取可能 / 受取済み / キャンセル済み（色分けあり）
+- **通知の既読化。** パネルの「既読にする」と一覧の「すべて既読」から
  元アプリの `mark_as_read` を Worker 経由で叩く
- **詳細の項目名は元 HTML の label を素通し。** 実物の編集画面は 開始日 / 終了日 / 概要 / 進捗 / 課題 / 計画
- **ページネーションは無い。** 実際の 1 ページ件数が分からないため
- **TA / 管理者画面は作っていない。** `/ta/**` `/admin/**` は取得したアカウントでは全て
  `/dashboard` にリダイレクトされた
  （2026-10 時点では TA 権限アカウントで `/ta/orders` 等に到達できるが、フォークは学生画面を対象のまま）
